## What EvidenceOS Is

EvidenceOS is an AI-powered copilot that helps EU financial entities prepare a submission-ready DORA Register of Information (RoI) draft from fragmented contracts, spreadsheets, and vendor inventories.

Core value:
- Ingest raw evidence (PDF, DOCX, XLSX, CSV).
- Extract structured entities (vendors, contracts, clauses, business functions).
- Normalize duplicates and aliases.
- Validate mandatory fields, formats, and relationships.
- Provide explainable AI recommendations (missing vendors, missing clauses, operational importance signals).
- Allow human review and approval.
- Export a versioned, submission-ready draft package (RoI, validation report, evidence report, audit summary).

Key constraints:
- AI assists; humans decide.
- Every recommendation must be explainable (evidence, reason, confidence).
- Every exported field must be traceable to source evidence where possible.
- EU-only data residency.
- Modular monolith with async workers (not microservices).

## Tech Stack

- Frontend:
  - Next.js
  - TypeScript
  - Tailwind CSS
  - shadcn/ui
- Backend:
  - FastAPI (Python)
  - Modular monolith with internal modules.
- Database:
  - PostgreSQL via Supabase (EU region).
  - JSONB for semi-structured payloads.
  - Vector support for retrieval.
- Storage:
  - Supabase Storage (EU).
- Workers:
  - Background job workers for:
    - OCR
    - parsing
    - extraction
    - normalization
    - validation
    - recommendation
    - export
- AI:
  - LLM API (e.g. GPT-5 or equivalent) for extraction reasoning and recommendation generation.
  - Embedding model for retrieval.
- Deployment:
  - Frontend: Vercel (EU region).
  - Backend: EU-hosted container (or similar).
  - Workers: EU-hosted container or queue-backed worker.

## How to Use This with an AI Code Assistant

### General Rules

- Work in phases, not “build everything at once”.
- Each prompt should:
  - State the phase and goal.
  - Reference which docs to use for context.
  - Specify constraints (e.g. “no external services except X”, “use Supabase”).
  - Ask for all generated files.
- When you finish a phase:
  - Summarize what was built.
  - List what remains from the roadmap.
  - Ask for the next phase prompt.

### Prompt Structure (Template)

Use this pattern:

```text
You are an expert full-stack developer.

Context:
- Product: EvidenceOS (AI-powered DORA RoI evidence & validation copilot).
- Docs to read: project_runbook.md, evidenceos_prd_v2_..., evidenceos_sdd_v1.md, evidenceos_domain_model_v1.md, ui_spec.md, api_spec.md, db_schema.md, milestone_roadmap.md, env_guide.md.

Goal:
- Implement [PHASE NAME] with [specific features].

Constraints:
- Use Next.js + TypeScript + Tailwind + shadcn/ui for frontend.
- Use FastAPI + Python for backend.
- Use Supabase PostgreSQL + Storage.
- No external services except [list].
- Keep code modular and testable.

Tasks:
1. [Task 1]
2. [Task 2]
...

Output:
- Generate all necessary files (code, config, migrations, etc.).
- Show the file structure.
- Explain how to run locally.
```

4. Phase 3: Validation engine + review UI.
5. Phase 4: Recommendations + review actions.
6. Phase 5: Export + audit + observability.
7. Phase 6: Polish, integration tests, deployment prep.

## Success Criteria

You have built the MVP when:
- A user can log in, create a workspace, and upload documents.
- The system can run a pipeline (OCR/parsing, extraction, normalization, validation, recommendations).
- A user can review validation results and recommendations, approve/reject/modify.
- The system can generate an export package with:
  - RoI draft.
  - Validation report.
  - Evidence report.
  - Review summary.
- All data is EU-hosted, versioned, and audit-loggable.
